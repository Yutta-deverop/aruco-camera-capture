# Android (Termux) 版 導入手順ガイド

スマホ1台で完結する構成です。**PC のビルド環境は不要**です。

```
┌─ Android スマホ ──────────────────────────────┐
│  IP Webcam（別アプリ） → localhost:8080 でMJPEG配信 │
│  Termux（本システム）                          │
│   ├─ MJPEG受信スレッド（main.py）                │
│   ├─ ArUco検出・切り抜き・GASアップロード          │
│   └─ Flask :5000 → ステータス＋プレビュー配信      │
└─────────────────────────────────────────────┘
              ↑ ブラウザで http://localhost:5000
```

---

## 1. アプリのインストール

| アプリ | 入手先 | 備考 |
|---|---|---|
| **Termux** | **F-Droid**（https://f-droid.org/packages/com.termux/） | ⚠️ Google Play 版は非更新で動かない。必ず F-Droid 版 |
| **IP Webcam** | Google Play（開発者: Pavel Khlebovich） | 代替: オープンソースの MJPEG 配信アプリでも可（配信URLさえ分かればOK） |

> Termux:API は**この構成では不要**です（カメラは IP Webcam 側が担当します）。

## 2. ファイルをスマホに入れる

この `android_termux/` フォルダの `main.py` と `install.sh` をスマホへ:

- **方法A（推奨・今後も使う）**: GitHub リポジトリを作って push → Termux で `pkg install git` → `git clone <URL>` → `cd` 
- **方法B**: PC でファイルの中身をコピー → Termux で `nano main.py` に貼り付け → `Ctrl+O` 保存 → `Ctrl+X`

## 3. セットアップ

```bash
bash install.sh
```

- OpenCV・numpy・Flask・requests をインストールし、`cv2.aruco` が使えるか自動チェックします
- **アーキテクチャ注意**: ARM32 端末（古い端末）だと `opencv-python` パッケージがない場合があります。その場合は arm64 必須

## 4. 起動

**順番が重要**です:

```bash
# ① IP Webcam を開いて「Start server」を押す
#    （画面に http://192.168.x.x:8080 と出ればOK。認証はOFFのまま）

# ② Termux でスリープ防止を有効化
termux-wake-lock

# ③ 起動
python main.py

# ④ 別アプリの Chrome で開く
#    http://localhost:5000
```

- トップページは自動で `http://localhost:5000/monitor/phone0` に飛びます
- ステータス＋**映像プレビュー**が同じ画面に出ます（マーカー検出状況が映った注釈付き映像）
- 終了: Termux で `Ctrl+C`

### 配信URLが違う場合

IP Webcam のポート設定や認証を変更した場合は `main.py` 冒頭の以下を変更:

```python
STREAM_URL = "http://127.0.0.1:8080/video"  # IP Webcam の MJPEG URL
CAM_ID = "phone0"                            # 監視画面のカメラ名
```

## 5. バックグラウンド（裏回し）実行

ブラウザを前面に出したまま・画面をオフでも動かすための設定:

### 必ずやる3つ

1. **`termux-wake-lock` を実行**（`python main.py` の前）
   - 実行後、通知バーに Termux の常駐通知が出ます（正常）
   - 解除は `termux-wake-lock` 再実行、または通知から
2. **バッテリー制限の除外**
   - 設定 → バッテリー → **Termux** → 「制限なし」
   - 設定 → バッテリー → **IP Webcam** → 「制限なし」
   - （機種により「バッテリー最適化」「デバイスメンテナンス」等の名前で存在）
3. **配信の常駐通知を消さない**
   - IP Webcam が裏で配信している間の通知は Android の仕様による必須通知です

### 端末依存の注意

- Samsung / Xiaomi / Huawei / OPPO 等は省電力が積極的なので、上記に加えて
  「開発者オプション → サーバーの常駐制限 無効化」「省電力モード中の除外」も確認
- **推奨: 充電しながら運用**（長時間常駐の安定性が大幅に向上）

### 常駐テスト（初回に必ず）

```bash
termux-wake-lock
python main.py
# → ブラウザでステータスを確認 → 画面オフ → 5分後に戻って
#   ブラウザ再オープンでステータスが更新されていればOK
# 問題なければ30分〜1時間放置テスト
```

## 6. 設定変更場所（main.py 冒頭）

| 設定 | 既定値 | 意味 |
|---|---|---|
| `GAS_URL` | 既存のGAS URL | Google Drive へのアップロード先 |
| `STREAM_URL` | `http://127.0.0.1:8080/video` | IP Webcam のMJPEG URL |
| `CAM_ID` | `"phone0"` | 監視画面のカメラ名（重複禁止） |
| `MIN_INTERVAL` | `5.0` | 撮影間隔の最小秒数 |
| `REQUIRED_STABLE_TIME` | `1.0` | 4マーカーを何秒維持したら撮影するか |
| `OUTPUT_WIDTH/HEIGHT` | `800` | 切り抜き画像サイズ |
| `FLASK_PORT` | `5000` | ステータス画面のポート |

## 7. トラブルシューティング

| 症状 | 対処 |
|---|---|
| 「映像ストリーム未接続」 | IP Webcam が起動しているか。`curl http://127.0.0.1:8080/video` 等で確認。ポート・URLが `STREAM_URL` と一致するか |
| プレビューが真っ黒 | IP Webcam のカメラ選択（背面カメラ）を確認 |
| マーカーが検出されない | マーカーIDが 0,1,2,3 の4x4_50 か。照明・距離を確認。プレビューに `Targets: n/4` が表示される |
| `cv2.aruco がありません` | `pkg reinstall opencv-python`。ARM32端末の場合はarm64端末を検討 |
| Driveに保存されない | `GAS_URL` のデプロイ状況をTermuxの出力で確認 |
| 画面オフで止まる | ①termux-wake-lock ②バッテリー制限除外 ③充電 ができているか再確認 |
| `pip install` が失敗する | `pkg install python` の pip と競合するため、numpy 等は `pkg install python-numpy` 系を使う（install.sh 済み） |

## 8. 次のステップ（案A: APK 化）

実用性が確認できたら、GitHub Actions のクラウドビルドで単一 APK にします
（Kivy 化して常駐通知・自動起動つきの本格アプリにする）。そのときはこの
`main.py` の ArUco・アップロード処理をそのまま流用します。
